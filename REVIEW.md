# REVIEW.md

## Code Review: Employee Attendance & Analytics API

This review identifies defects in the original starter `app/main.py`, how to reproduce them, and the recommended fixes implemented in the replacement.

| # | Location | What is wrong | How to notice it | How it is fixed |
|---:|---|---|---|---|
| 1 | `compute_late_minutes` | Uses naive wall-clock datetime calculations and anchors shift start to the punch-in date. This can produce incorrect results across timezones and overnight shifts. Timestamp precision is also not explicitly normalized before calculation. | Test a punch-in around the 10-minute grace boundary and a punch-in after midnight for a 22:00–06:00 shift. | Normalize instants consistently to UTC, calculate shift boundaries in IST using the attendance date, and truncate instants to whole seconds before calculation and storage. |
| 2 | `compute_work_hours` | Python's built-in `round()` uses ties-to-even rounding, which does not satisfy the required decimal half-up rounding rule. | Test a duration whose hour value is exactly halfway between two values at two decimal places. | Use `Decimal` with `ROUND_HALF_UP` to round work hours to two decimal places. |
| 3 | `compute_overtime` | Always anchors shift end to the attendance date, which gives the wrong shift-end instant for overnight shifts. | Test a 22:00–06:00 shift with a punch-out at 06:40 the following day. | Calculate shift end on the following calendar day when `shift_end <= shift_start`. |
| 4 | `compute_overtime` | Counts any positive overtime, although the contract requires at least 30 whole minutes before overtime is counted. | Punch out 20 minutes after the scheduled shift end. | Calculate floored whole minutes and return zero when overtime is below 30 minutes. |
| 5 | `/health` | Returns success without verifying that MongoDB is reachable. | Stop or disconnect MongoDB and call `/health`. | Ping MongoDB and return HTTP 503 when the database is unavailable. |
| 6 | `EmployeeIn` / `create_employee` | The starter model does not enforce the employee-creation contract's input constraints, including employee-code format, email format, shift-time format, valid joining date, and different shift start and end times. | Submit an invalid employee code, malformed email, invalid shift time or date, or identical shift times. | Validate the required formats and lengths, validate `joined_on`, and reject identical shift start and end times with HTTP 422. |
| 7 | `create_employee` | Checking for an existing employee before insertion is not sufficient to prevent duplicate employee codes during simultaneous requests. | Send concurrent creation requests with the same `emp_code`. | Create a unique MongoDB index on `emp_code` and handle duplicate-key errors with HTTP 409. |
| 8 | `create_employee` | Uses `datetime.now()`, which creates a naive machine-local timestamp, and does not serialize `created_at` as epoch milliseconds as required by the API contract. | Inspect the stored timestamp and compare the response value with the required timestamp format. | Store the creation time as a UTC BSON datetime and serialize the API value as integer epoch milliseconds. |
| 9 | `list_employees` | Uses `skip = page * page_size`, which skips the first page when page numbering starts at 1. | Request page 1 with a page size of 20. | Calculate the offset as `(page - 1) * page_size`. |
| 10 | `list_employees` | Counts all employees instead of only employees matching the department filter, and does not guarantee the required stable sort order. | Request a department-filtered page and compare `total` with the number of matching employees. | Apply the same filter to the count and result query, and sort by `emp_code` ascending. |
| 11 | `list_employees` | Does not validate pagination bounds. The contract requires `page >= 1` and `1 <= page_size <= 100`. | Request `page=0`, `page_size=0`, or `page_size=101`. | Validate pagination parameters and return HTTP 422 for invalid values. |
| 12 | `punch_in` | An unknown employee can cause an error when the starter accesses fields on a missing employee record instead of returning HTTP 404. | Punch in using an unregistered employee code. | Check employee existence before accessing employee fields and return HTTP 404 if the employee does not exist. |
| 13 | `PunchInIn` / `punch_in` | The starter uses a truthiness check for `punched_at`, so zero is treated as if no timestamp were supplied. It also does not strictly validate epoch-millisecond timestamps. | Supply zero, a seconds-looking timestamp, a float, a string, or an out-of-range value. | Distinguish `None` from supplied values and accept only integer epoch milliseconds in the inclusive range `100000000000`–`4102444800000`. Reject invalid values with HTTP 422. |
| 14 | `punch_in` | Derives the attendance date using the host's local date rather than the required IST attendance-date rule. Overnight shifts require an additional date adjustment. | Test a timestamp near midnight IST and a punch-in before the shift end of an overnight shift. | Use the IST calendar date of `punch_in`; for overnight shifts where `shift_end <= shift_start`, assign a punch-in whose IST time is earlier than `shift_end` to the shift that started the previous day. |
| 15 | `punch_in` | The duplicate-record check and insertion are separate operations, so concurrent requests can both pass the check and attempt to insert the same employee's attendance record. | Send simultaneous punch-in requests for the same employee and attendance date. | Enforce a unique compound index on `(emp_code, date)` and translate duplicate-key errors into HTTP 409. |
| 16 | `PunchInIn` / `punch_in` | The starter accepts a generic string for status rather than enforcing the allowed punch-in statuses. It also does not consistently normalize timestamps to whole seconds before storage. | Submit `ABSENT` or `LEAVE` as the punch-in status, or provide a timestamp with fractional seconds. | Accept only `PRESENT`, `WFH`, and `ON_DUTY`; truncate valid instants to whole seconds before calculations, storage, and response serialization. |
| 17 | `list_attendance` | Loads all matching records into Python before sorting and paginating. This is inefficient and does not meet the requirement to remain fast on approximately 100,000 attendance records. | Run the endpoint against a large attendance collection and inspect query behavior and memory usage. | Apply filters, sorting, `skip`, and `limit` in MongoDB, and calculate `total` using a database count with the same filters. |
| 18 | `list_attendance` | Sorts only by date, leaving the order of records sharing a date unspecified. It also returns a derived `id` based on MongoDB's internal `_id`, which must not appear in API responses. | Create attendance records for multiple employees on the same date and inspect ordering and response fields. | Sort by date descending and `emp_code` ascending, and exclude `_id` and derived identifiers from responses. |
| 19 | `list_attendance` | Does not validate date formats, reversed date ranges, allowed status values, or pagination bounds. | Try an invalid date, `date_from > date_to`, an unsupported status, `page=0`, or `page_size=101`. | Validate query parameters, require valid ISO dates and supported statuses, and return HTTP 422 for invalid input. |
| 20 | Starter endpoint set | The required punch-out, manual regularization, monthly analytics, department summary, late leaderboard, department trend, and explain endpoints are listed as TODOs and are not implemented. | Compare the starter routes with the endpoints marked for implementation in `openapi.yaml`. | Implement all required routes with the specified response fields, status codes, validation, and concurrency behavior. |
| 21 | Analytics implementation | The starter does not implement the required analytics. The contract requires MongoDB aggregation pipelines, including correct handling of employees without logs, ranking ties, weekend records, and calendar days without attendance records. | Test employees with no logs, a tie at the leaderboard cutoff, weekend attendance, mid-month joiners, and dates with no records. | Use MongoDB aggregation pipelines and appropriate indexes; use competition ranking for leaderboard ties and database-side date gap filling for department trends. |

## Examined and Not Considered Defects

- `emp_code` is the customer-generated business identifier. MongoDB `_id` is internal and must not appear in requests or responses.
- `PRESENT` is the correct default punch-in status. `WFH` and `ON_DUTY` are also valid punch-in statuses.
- The starter attendance-list slice `(page - 1) * page_size : page * page_size` uses the correct offset formula. The principal issues are loading all matching records into Python and using an incomplete sort.
- Returning HTTP 404 for `/` is not a defect because the contract does not require a root endpoint.
- A weekday with no attendance record is different from an `ABSENT` record. Analytics must preserve this distinction.
